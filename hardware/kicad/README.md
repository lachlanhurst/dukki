# KiCad library: WeAct STM32G474 core board

Footprint and symbol for the WeAct Studio STM32G474 core board V1.0, QFN48 (STM32G474CEU6) variant, the bridge MCU board in this project. Generated by `scripts/kicad/gen_weact_kicad.py` from WeAct's board outline drawing and schematic in `docs/datasheets/`. Edit the script, not the files.

Files:

- `WeAct_STM32G474CoreBoard.pretty/WeAct_STM32G474CoreBoard_QFN48.kicad_mod`, the footprint. KiCad 8 format.
- `WeAct_STM32G474CoreBoard.kicad_sym`, the matching symbol, pin names as on the board silkscreen.
- `3d/`, 3D models. `AMASS_XT30U-M.step` and `LSM6DSV16X_Breakout.step` are made by `scripts/kicad/gen_3d_models.py` (CadQuery) and committed. `WeAct_STM32G474_raised.step` is derived by the same script from WeAct's own model, which is not committed (WeAct's file, 6 MB). Fetch WeAct's model, then derive:

```sh
curl -L -o hardware/kicad/3d/WeAct-STM32G47x_CoreBoard_3D.step \
  "https://raw.githubusercontent.com/WeActStudio/WeActStudio.STM32G474CoreBoard/master/Hardware/QFN48/WeAct-STM32G47x_CoreBoard_3D.step"
```

Adding to a project: Preferences, Manage Footprint Libraries, add `${KIPRJMOD}/../hardware/kicad/WeAct_STM32G474CoreBoard.pretty` with nickname `WeAct_STM32G474CoreBoard`; Manage Symbol Libraries, add the `.kicad_sym` with the same nickname. The symbol's footprint field already points at `WeAct_STM32G474CoreBoard:WeAct_STM32G474CoreBoard_QFN48`. The footprint's 3D model path is `${KIPRJMOD}/../kicad/3d/WeAct_STM32G474_raised.step`, right for a project in `hardware/<name>/`. Derive that model with `uv run --python 3.12 --with cadquery python scripts/kicad/gen_3d_models.py hardware/kicad/3d/WeAct-STM32G47x_CoreBoard_3D.step`: it drops WeAct's tall headers, centres the board on the footprint and lifts it 1 mm above the carrier on short pins.

Geometry, from the WeAct drawing:

| Item | Value |
|---|---|
| Board | 36.28 x 28.14 mm, corner radius about 2 mm (estimated) |
| Headers | two 2 x 12, 2.54 mm pitch, along the long edges |
| Outer row to board edge | 1.37 mm |
| First column to USB-C edge | 6.97 mm; last column 1.37 mm from the other edge |
| Pads | 1.7 mm round, 1.0 mm drill (KiCad pin-header convention); pads 1 and 25 square |
| Courtyard | board plus 0.25 mm, plus 1 mm on the USB-C edge for the receptacle |

Pad numbering: pads 1 to 24 are schematic connector P1, the VCC side (VCC, VCC, GND, GND, PB12, PB13, ...), pads 25 to 48 are P2, the 3V3 side (3V3, 3V3, GND, GND, PB10, PB11, ...). On P1 the odd pads are the outer row and the even pads the inner row; on P2 the odd pads are the inner row. The two headers are the same part placed the same way round, so their odd pins sit on the same side; WeAct's silkscreen gives one label line per row, the upper line naming the upper row (checked on the board: PB13 is on P1's inner row). Rev A had odd pads inner on both headers, which mirrored every P1 signal onto its column neighbour; do not "correct" it back. Every pad carries its pin name as the pad function, so hovering in pcbnew shows it. The LQFP48 (CBT6/CET6) variant of the board has the same outline and grid; on it the four positions carrying PC4, PC6, PC10 and PC11 here are not connected, and its blue LED is on PA8.

Not yet verified by opening in KiCad; the files were generated and checked structurally. Open the footprint in the editor once and run DRC on the first board that uses it.

Community alternatives found (KN-NaMi/Tip-Etcher and Patryk2k04/NaMi_DevBoard on GitHub) are drawn for the QFN variant, carry no licence and use a 0.76 mm drill, which does not accept a 0.64 mm square header pin. Not used.

# KiCad library: LSM6DSV16X breakout

Footprint and symbol for the generic LSM6DSV16X breakout used as the trunk IMU (`docs/datasheets/lsm6dsv16xtr.png`). Generated by `scripts/kicad/gen_lsm6dsv16x_kicad.py`; edit the script, not the files. Add `LSM6DSV16X_Breakout.pretty` and `LSM6DSV16X_Breakout.kicad_sym` to a project the same way as the WeAct library, with nickname `LSM6DSV16X_Breakout`.

Measured from the photo, scaled by the 7-pin row's 2.54 mm pitch:

| Item | Value | Confidence |
|---|---|---|
| 7-pin row | VCC, GND, AD0/MISO, SDA/MOSI, SCL/SCLK, CS, INT1, left to right seen from the component side; pad 1 (VCC) square | exact: 2.54 mm grid, both views agree |
| Row to bottom board edge | 1.27 mm to the pad centres, row centred across the board | good |
| Board | about 17.8 x 15.0 mm | about ±0.4 mm; fab and courtyard only, courtyard 0.5 mm out |
| 3-pin row (SDX, SCX, INT2) | above pins 3 to 5, 12.0 mm from the 7-pin row, pads 8 to 10 | measured on the part (11/10/2026); unused, holes for support only, not connected |
| Mounting holes | near the top corners, about 6.8 mm either side of centre and 11.5 mm above the 7-pin row | estimate, fab layer only |

The breakout mounts components up, labelled side down on the carrier. The chip's X axis points right and Y towards the 3-pin row in the footprint's view, Z up out of the carrier; the fab layer draws the arrows. 

# Project symbols: Dukki.kicad_sym

Written by `scripts/kicad/gen_bridge_sch.py` from KiCad's own libraries: `LMR51606` (TI buck, KiCad's LMR50410 symbol, same SOT-23-6 pinout) and `Q_PMOS_GDS` (KiCad's Q_PMOS numbered for TO-252: 1 gate, 2 drain, 3 source). The bridge carrier project is in `hardware/bridge/`.

The WeAct symbol's second 3V3 pin (26) is passive rather than power output, so ERC sees one driver on the +3V3 net when both pins are tied.

# Head library: DukkiHead.kicad_sym and DukkiHead.pretty

Written by `scripts/kicad/gen_head_kicad.py` (on the KiCad VM); edit the script, not the files. Used by the head carrier project in `hardware/head/` (`docs/head-pcb.md`).

| Item | Source |
|---|---|
| `DF40C_Socket_CM4_1-100`, `DF40C_Socket_CM4_101-200` footprints | the pads of the `Raspberry-Pi-4-Compute-Module` footprint in Raspberry Pi's CM4 IO board KiCad design (`CM4IO-KiCAD.zip`, datasheets.raspberrypi.com), one footprint per socket so JLC places two DF40C-100DS-0.4V(51). Origin at the socket's centre |
| `Radxa_CM4_Module` footprint | the same footprint's four 2.7 mm NPTH (M2.5, 33 x 48 mm) with a 40 x 55 mm outline and courtyard, so no part lands under the module. Origin at the module's centre; the sockets go at (-16.96, 2.5) and (16.96, 2.5) from it, as each socket footprint's description says |
| `Radxa_CM4_1-100`, `Radxa_CM4_101-200` symbols | the two units of Raspberry Pi's `ComputeModule4-CM4` symbol, as two symbols to match the two socket footprints. The Radxa CM4 keeps the Pi assignment on these pins |
| `FPC_XUNPU_FPC-1.0HF-15PWAR-H20_1x15-1MP_P1.0mm` footprint | LCSC C19269369's land pattern from the EasyEDA library (easyeda2kicad), anchor pads renamed MP |
| `LMR51635` symbol | KiCad's LMR50410 drawing renumbered to the LMR516x5 pinout: 1 FB, 2 EN, 3 VIN, 4 GND, 5 SW, 6 CB (not the LMR51606's order) |
| `MAX98357A` symbol | KiCad's, with the exposed pad typed passive so tying it to ground raises no ERC warning |
| `BMI088` symbol | KiCad's, with SDO1 and SDO2 passive: on this board they strap the I2C addresses to a rail, which ERC rejects for output pins |
| `SolderJumper-2_Wide_Bridged_3A` footprint | a bridged solder jumper for up to 3 A: 2 x 3 mm pads 0.6 mm apart joined by a 1.2 mm copper strip, mask open over it for cutting; a net tie like KiCad's `SolderJumper-2_P1.3mm_Bridged`. The head's 5 V and amplifier links |
| `BMI088_Module` footprint and symbol (no longer on the head board; kept for an external module) | drawn from `hardware.md` 6.2 and `docs/datasheets/bmi088-module-*.png`: 15 x 20 mm, rows 11 mm apart (measured), INT row offset 1.5 pitches from pad 1 (seller's diagram, confirmed on the module 12/10/2026). Mounting holes not drawn |

The vendored sources, upgraded to the KiCad 10 format and with their 3D model paths removed, are in `vendor/`. Raspberry Pi publishes the CM4 IO design files for carrier board designers; their README leaves terms for the 3D models with the manufacturers, and none are copied here.
